# 生意记账模块

生意代码独立于家庭业务，包名为 `com.base.business`。本模块仅依赖 `base-security`（含 `base-common`）和 JDBC，不依赖 `system-service`，不调用家庭 Service。当前由 `system-service` 作为启动程序，以 runtime 依赖装配；家庭源码无法通过这项依赖导入生意类。

`BusinessAutoConfiguration` 自动装配生意接口和 Service。设置 `business.enabled=false` 或启动参数 `--business.enabled=false` 可关闭生意接口和业务 Bean；登录、家庭接口继续使用。以后移除运行时依赖时保留已执行的数据库迁移及历史。

## 已实现接口

所有接口需要现有登录 Token，返回既有 `{ code, message, data }` 结构。一个账号就是一本生意总账。每次操作以 Token 中的账号 ID 匹配 `owner_id`，家庭成员身份不能访问其他账号的生意。无需创建、命名、选择账套或管理生意成员。ID 返回字符串，金额为整数分。

| 方法 | 路径 | 请求 |
| --- | --- | --- |
| GET | `/business/customer/list` | 选填 `type`、`keyword`、`pageNum=1`、`pageSize=20`（最多100） |
| GET | `/business/customer/detail` | `id` |
| POST | `/business/customer/create` | `type`、`name`、`requestId`；选填 `appellation`、`phone`、`remark` |
| POST | `/business/customer/update` | `id`、`type`、`name`；选填 `appellation`、`phone`、`remark`；完整资料更新 |
| POST | `/business/customer/delete` | `id`；只删除当前账号的客户档案 |

客户类型为 `farmer`（农户客户）或 `merchant`（商家客户）。姓名最多30字，称谓/电话最多30字，备注最多200字；requestId 最多80字。同一创建请求重试不重复插入；同一请求编号配不同内容返回409。客户列表支持按姓名/称谓包含搜索，按创建时间和ID倒序分页。

删除前必须应收和应付分别为0；净余额为0但仍存在双向未结款时返回409，须实际结清或完成抵账。删除在事务中与客户创建、修改使用同一账号锁，并锁定客户行。通过 `deleted_at` 隐藏档案，不删除客户实体或任何历史买卖、结算及分配记录。列表、详情和修改排除已删除客户；重复删除同一账号的客户成功，跨账号或不存在的客户返回404。重试已删除客户的原创建请求返回409，不恢复档案；重新新增须使用新 requestId。

小程序从右下角加号进入新增，列表左滑或长按依次显示“修改 / 删除”，详情也可进入修改。新增和修改共用五字段表单：客户类型直接点选，姓名/名称必填，称谓自由输入，称谓、电话、备注选填；保存成功返回并刷新列表。删除前确认，失败保留客户行并展示原因。

客户详情及列表包含资料和以下金额：

| 字段 | 含义 |
| --- | --- |
| `fertilizerBalanceCents` | 化肥剩余应收减应付 |
| `grainBalanceCents` | 粮食剩余应收减应付 |
| `balanceCents` | 当前净余额 |
| `receivableCents` / `payableCents` | 分别保留尚未核销的应收/应付，避免净额掩盖双向未结 |
| `settled` | 只有应收、应付同时为0才为true |

正数表示对方欠我们，负数表示我们欠对方。化肥原单1000元、收款分配500元、收粮1200元，返回 `50000 / -120000 / -70000`。净额0但应收应付都未核销时，前端显示“待抵账”。跨季通过原单、经营季和结算分配追溯，不复制期初欠款。

## 数据和本阶段范围

账号归属迁移 V4.3 位于启动程序的 `db.system` 迁移基础设施，通过元数据兼容 PostgreSQL/H2，历史不会随业务模块停用而缺失。原 SQL 源文件位于 [sql/business](../sql/business)，表均属于 `business` schema：`biz_customer`，以及客户余额查询所需的 `biz_trade`、`biz_trade_item`、`biz_settlement`、`biz_settlement_item`。

部署仍使用一个数据库和一条 Flyway 历史，启动程序统一打包根目录 SQL 到 `db/system`。业务源码拆模块与迁移历史是不同职责；停用生意功能时不删除迁移，不删除生意数据，不破坏家庭启动的历史校验。公共账号ID用于数据归属和审计，生意表不引用家庭表。

本阶段已接前端客户列表、新增/修改/删除、详情。V4.4 新增删除时间，旧客户默认正常，历史迁移原文保留。**尚未提供**买卖、收付款、抵账录入接口、商品、库存或利润统计。已有结算表是查询基础，未来写接口必须事务校验客户未删除、核销方向、金额上限及抵账两侧平衡，并复用账号/客户锁；禁止客户端直接设置客户余额。

模式切换只保存本机当前账号的页面偏好，无切换接口，不需要初始化总账或同步家庭数据。

本次18项相关后端测试通过，包含隔离 H2 的迁移及 HTTP 测试、权限越界、幂等、删除校验、已删除客户不可修改、历史保留、部分还款、多次分配、抵账、撤销、跨季和停用生意后家庭仍可用。H5另以独立临时H2服务验收新增与修改回填、清空选填称谓。当前未在真实 PostgreSQL 执行迁移。

V4.3 将旧账套中的客户、买卖和结算归到原账套创建账号，保留记录 ID、金额和操作审计；同一账号的多个旧账套合并到该账号。旧成员授权不再使用。`book/create`、`book/list` 已移除，客户请求和响应均不包含 `bookId`。
