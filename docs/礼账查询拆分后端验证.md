# 礼账接口职责拆分后端验证

日期：2026-10-29。基线 HEAD：`da9ba4b`。范围仅为后端查询及必要响应契约；未提交、部署、停止已有8000端口服务或修改真实账目。

## 实现与兼容

在现有 `LedgerService`、`HouseholdService`、`MoneyService`、`FriendService` 增加独立查询；`LedgerQueries` 负责校验，`LedgerReadResponses` 明确返回结构。没有增加通用查询服务、缓存层、ORM或数据库迁移。

- 收支、人情、账簿、账户详情按当前家庭+ID查询，关联名称由同一家庭的SQL连接取得；已软删除分类仍返回状态。
- 人情、借贷、账簿、亲友汇总和收支列表在数据库分页；计数和列表复用同一业务筛选。默认20条、最大100条，原亲友选择器默认10条保持。
- 收支汇总/月份/分类、人情、借贷、账簿统计在数据库求和/分组；不读取全量快照在Java筛选。亲友只对当前页ID批量执行两条聚合SQL，不按亲友逐条查询。
- 收支列表额外返回当前页涉及月份的完整筛选合计 `monthSummaries`，避免页尾只加载半月时月头合计缩水。人情来源的收支行增加 `bookName`。
- 账户详情/列表、资金概览、写入余额校验复用同一SQL增减聚合，覆盖期初、普通收支、手动存款现金调拨、转账、校准和借贷。单账户先限定targets，其他账户流水不参与该账户聚合。
- 最近记录保留原“按最近更新”口径，每个来源按updated_at（空则created_at）和ID先LIMIT，再在最多3×limit个候选中按同一规则排序，默认5条、上限20条；包含projectId，旧未关联账户的人情保留null；普通收支候选排除人情/借贷辅助记录。
- 五组历史资源分别分页，只接受隐藏历史家庭的原账号，保持只读；历史收支不初始化配置，不使用当前家庭分类解释历史。
- 旧 `/ledger/data`、`/ledger/history/data` 保留原全量语义供旧客户端兼容，Controller注释明确兼容用途。写入与确认规则未改。

完整路径和字段说明已补在 [Java后端接口与数据库规划](Java后端接口与数据库规划.md) 顶部。

## 测试证据

先添加 `LedgerQueryHttpTest` 并运行，两个查询用例均因新增路径404失败，再实现查询。后续为历史冲减和跨页月头统计分别观察到“期望-2000实际2000”和缺少monthSummaries的失败，再补实现，保留断言。

新增9个HTTP用例均通过，覆盖：直接详情、家庭隔离、20条分页和第2页、全范围金额、日期/方向/页大小校验、旧空日期回退、软删分类、非现金净存入、账户余额、年份补齐12月、双向待收待还、不同时期/方向/账簿/亲友筛选、五组历史分页权限、历史signed saving、月头完整合计、固定查询量和100/1,000/10,000条体积。

读取路径用Mockito监测真实HTTP过程中现有实体Mapper：独立详情/列表/统计/最近记录未调用全量实体集合Mapper；亲友汇总在1条/100条页大小下均只调用2条批量分组SQL。既有读路径测试只补充JdbcTemplate构造依赖，原有断言保留。

## 体积与数据库验证

见 [H2规模样本](礼账查询H2规模验证.md)：在隔离测试库插入100、1,000、10,000条人情。详情包含统一响应外壳时字节数严格固定378，20条分页保持约7KB，旧全量随条数增长至约3MB。该用例以人情为规模样本，其他业务的金额与权限由独立回归覆盖；连续首次/二次请求没有清理数据库/JVM缓存，不能将首次当严格冷缓存。

见 [PostgreSQL执行计划](礼账查询拆分PostgreSQL执行计划.md)：真实配置只读事务执行6组 `EXPLAIN (ANALYZE, BUFFERS)`，包括收支分页/汇总、人情分页、账簿分页、亲友批量聚合、账户余额聚合；账户聚合报告对应最终targets版本。执行完回滚；凭据和家庭ID未写进报告。现有最大样本家庭只有4条人情、17条收支，记录的毫秒数不证明大规模生产性能，因此本次没有凭猜测创建索引。
