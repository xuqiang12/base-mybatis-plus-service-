# 基础规范与运行说明

## 模块归属

当前有两个公共类库和两个独立运行的服务：

| 模块 | 运行方式 | 内容 |
| --- | --- | --- |
| base-common | 被引用，不启动 | 返回、校验、异常、日志、健康检查、时间 |
| base-security | 被引用，不启动 | Token 公钥校验、身份提供接口、权限检查和安全错误 |
| system-service | 独立启动，8080 | 登录、用户、角色、菜单、权限及身份授权查询 |
| relations-service | 独立启动，8081 | 亲友业务；远程取得共享身份授权 |

公共入口分别是 `BaseCommonConfiguration` 和 `BaseSecurityConfiguration`。安全入口导入通用基础，两者都不扫描业务包。system 只扫描 `com.base.system`，relations 只扫描 `com.base.relations`。

管理源码在 `system-service/src/main/java/com/base/system/modules/`，公共安全代码在 `base-security/src/main/java/com/base/security/`。MyBatis 配置和 Mapper 归 system；relations 将来有业务表时自行引入数据库依赖和业务 Mapper 扫描。

不需要认证的新服务只引用 common、导入公共入口即可；有登录要求的服务引用 security，并提供 `CurrentUserProvider.currentUser(int userId, String token)` 实现。公开业务路径通过 `security.public-endpoints.get/post` 明确指定，例如：

```yaml
security:
  public-endpoints:
    get:
      - /public/news
```

这些配置仅改变明确列出的路径。健康检查和开启的文档接口公开；system 额外公开登录和注册，其他接口默认要求身份。

## 数据库准备

需要 JDK 21、Maven 3.9.x；system 还需要独立 PostgreSQL 数据库。relations 当前不配置数据库。此实现不读取原 Node 数据，不迁移原数据。

在 PostgreSQL 工具中执行，先替换密码：

```sql
CREATE USER relations WITH PASSWORD '替换为自己的数据库密码';
CREATE DATABASE relations OWNER relations;
```

system 启动时 Flyway 创建 `relations` schema、8 张基础表和 18 个初始权限。手写 SQL 集中在根目录 `sql/`，按发布版本分目录；当前 V1 位于 `sql/1.0.0/V1__identity_foundation.sql`，文件名和内容没有修改。system 的 POM 登记本服务的脚本，将它原样打包到 `db/system/1.0.0/`，Flyway 继续按 `classpath:db/system` 递归加载。已有数据库由 system 配置连接，不需要重建。后续变更放在新的发布版本目录，增加 V2 等脚本并在所属服务 POM 中登记，不能修改已执行的 V1。详见 [数据库脚本说明](../sql/README.md)。

## 本机 RSA 密钥

在项目根目录使用 **PowerShell 7** 执行一次，生成本机专用密钥。以下代码遇到已有文件会停止，避免覆盖正在使用的密钥：

```powershell
Set-Location 'F:\公司项目\gitee\base-mybatis-plus-service'
if ((Test-Path './config/jwt-private.pem') -or (Test-Path './config/jwt-public.pem')) {
    throw '密钥文件已存在，请使用现有密钥'
}
New-Item -ItemType Directory -Path './config' -Force | Out-Null
$taskRsa = [Security.Cryptography.RSA]::Create(2048)
[IO.File]::WriteAllText((Join-Path (Get-Location) 'config/jwt-private.pem'), $taskRsa.ExportPkcs8PrivateKeyPem())
[IO.File]::WriteAllText((Join-Path (Get-Location) 'config/jwt-public.pem'), $taskRsa.ExportSubjectPublicKeyInfoPem())
$taskRsa.Dispose()
```

本机 `config/*.pem` 已被 Git 忽略。测试资源中的 `test-private.pem`、`test-public.pem` 仅用于自动化测试，不可用于实际运行。

system 私钥采用 PKCS#8 的 `BEGIN PRIVATE KEY` 格式，公钥采用 X.509 的 `BEGIN PUBLIC KEY` 格式；relations 只需要公钥。双方 issuer 默认 `system-service`，必须一致。由 HS256 切换为 RS256 后，旧 Token 失效，需要重新登录。

## 构建和运行

在项目根目录构建：

```powershell
$env:JAVA_HOME = 'D:\DevTools\jdk-21.0.12.1+1'
$env:Path = "$env:JAVA_HOME\bin;$env:Path"
mvn.cmd -s .mvn/settings.xml clean verify
```

终端一设置 system 的配置并运行。以下绝对路径可避免 IDEA 或终端工作目录不同导致找不到密钥：

```powershell
$env:DB_URL = 'jdbc:postgresql://localhost:5432/relations'
$env:DB_USERNAME = 'relations'
$env:DB_PASSWORD = '填写自己的数据库密码'
$env:JWT_PUBLIC_KEY = 'file:F:/公司项目/gitee/base-mybatis-plus-service/config/jwt-public.pem'
$env:JWT_PRIVATE_KEY = 'file:F:/公司项目/gitee/base-mybatis-plus-service/config/jwt-private.pem'
$env:BOOTSTRAP_ADMIN_USERNAME = 'admin'
$env:BOOTSTRAP_ADMIN_EMAIL = '填写自己的管理员邮箱'
$env:BOOTSTRAP_ADMIN_PHONE = '填写自己的手机号'
$env:BOOTSTRAP_ADMIN_PASSWORD = '填写自己的管理员密码'
& "$env:JAVA_HOME\bin\java.exe" -jar .\system-service\target\system-service-0.0.1-SNAPSHOT-exec.jar
```

终端二同样设置 JAVA_HOME，配置公钥并启动 relations：

```powershell
Set-Location 'F:\公司项目\gitee\base-mybatis-plus-service'
$env:JAVA_HOME = 'D:\DevTools\jdk-21.0.12.1+1'
$env:JWT_PUBLIC_KEY = 'file:F:/公司项目/gitee/base-mybatis-plus-service/config/jwt-public.pem'
$env:SYSTEM_ACCESS_URL = 'http://localhost:8080/auth/access'
& "$env:JAVA_HOME\bin\java.exe" -jar .\relations-service\target\relations-service-0.0.1-SNAPSHOT-exec.jar
```

分别访问 `http://localhost:8080/health` 和 `http://localhost:8081/health`。覆盖端口可以使用 `--server.port=...`；system 地址改变时，要同时更新 relations 的 `SYSTEM_ACCESS_URL`。

可执行包带 `-exec.jar`，普通 JAR 用于模块依赖。环境变量仅影响当前终端；实际运行使用固定密钥，不要每次启动重新生成。

IDEA 分别运行 `SystemApplication` 和 `RelationsApplication`，配置步骤见 [IDEA配置与运行流程](IDEA配置与运行流程.md)。两个服务均提供 `application-local.example.yml`，可以分别复制为 `application-local.yml` 并填写本机参数。该文件既被 Git 忽略，也被 Maven 资源打包排除，运行时必须显式加载。

例如 system 的程序参数：

```text
--spring.profiles.active=local --spring.config.additional-location=file:F:/公司项目/gitee/base-mybatis-plus-service/system-service/src/main/resources/application-local.yml
```

relations 的本机文件同理改为它自己的路径。路径包含空格时将整个文件位置参数用双引号括起来。直接使用前文环境变量运行 JAR 时不需要加载本机配置。

system 的初始化邮箱为空时不创建管理员；显式填写邮箱后会校验其余信息，且只在整张用户表为空时创建第一名超级管理员。重启不会覆盖已有用户。公开注册只能创建普通用户。

## 返回、参数与错误

查询统一 GET，写操作统一 POST，JSON 请求体使用 `Content-Type: application/json`。管理接口用 `Authorization: Bearer <token>`。

成功 HTTP 200：

```json
{"code":0,"message":"success","data":{}}
```

普通 Controller 直接返回数据，由公共 `ResponseAdvice` 包装；已返回 `ApiResponse` 的不重复包装。新增、修改、删除返回的 `data` 是对应成功提示字符串。用户列表分页返回：

```json
{"code":0,"message":"success","data":{"list":[],"total":0,"pageNum":1,"pageSize":10}}
```

`pageNum` 默认 1，`pageSize` 默认 10，最大 100。时间输出为北京时间 `yyyy-MM-dd HH:mm:ss`。数据库存储带时区的时间。

错误的 HTTP 状态与 `code` 一致：400 参数/业务冲突、401 未登录或认证失效、403 无权限、404 资源不存在、500 内部错误、503 统一身份服务暂不可用。例如：

```json
{"code":403,"message":"无操作权限","data":null}
```

内部异常记录在服务端日志，响应不返回 SQL 和异常堆栈。请求日志只记录方法、路径、状态和耗时。

## 登录与权限

`POST /auth/login` 使用邮箱和密码：

```json
{"email":"自己的管理员邮箱","password":"自己的管理员密码"}
```

成功后从 `data.token` 取得 JWT，默认有效期 7 天。密码使用 BCrypt 散列，用户查询和当前用户接口均不返回密码或散列。

`GET /auth/userInfo` 返回 `data.userInfo`、`data.permissions` 和 `data.menus`。菜单决定前端可见页面；权限码决定按钮显示和后端操作，二者分别授权。仅取得菜单不能操作对应 API；前端隐藏按钮也不能代替后端权限校验。

system 每次请求从数据库读取当前用户与最新授权。relations 先用公钥校验 Token，再携带原 Token 调用 system 的 `GET /auth/access`；system 返回的是该 Token 的当前认证主体，不接受匿名 userId 授权查询。双方都不使用 JWT 中的旧角色、权限和管理员声明作为授权依据。软删除用户后旧 Token 失效，修改角色授权后旧 Token 按新权限执行。内部 authority 的普通权限以 `permission:` 为前缀，与管理员身份隔离；对外仍返回 `system:user:list` 等原始权限码。

relations 不缓存授权。默认连接超时 2 秒、读取超时 3 秒；无自动重试。统一身份服务返回身份失效时为 401，故障或异常响应时为 503，不能放行业务；健康检查仍公开。

超级管理员可访问全部基础管理接口，至少保留一名有效超级管理员；只有超级管理员可以设置或修改管理员身份。`system:` 基础权限码不能删除或改 code，可以修改显示名称。

## 接口清单

以下管理和认证接口均在 system（默认 8080）；relations（默认 8081）仅有健康检查和后续业务接口。除健康检查、登录、注册外，均要求有效 JWT；管理接口还要求对应权限或超级管理员身份。

| 方法 | 路径 | 请求要点 | 操作权限 |
| --- | --- | --- | --- |
| GET | `/health` | 无参数 | 公开 |
| POST | `/auth/login` | email、password | 公开 |
| GET | `/auth/userInfo` | 无参数 | 已登录 |
| GET | `/auth/access` | 返回当前 LoginUser：id、username、email、avatar、isSuperAdmin、roles、permissions | 已登录 |
| POST | `/user/register` | username、email、phone、password；avatar 可选 | 公开 |
| GET | `/user/list` | pageNum、pageSize；username/email/phone/includeDeleted 可选 | `system:user:list` |
| GET | `/user/detail` | id | `system:user:detail` |
| POST | `/user/create` | 注册字段；isSuperAdmin、roleIds 可选 | `system:user:add` |
| POST | `/user/update` | id；修改字段和 roleIds 可选 | `system:user:edit` |
| POST | `/user/delete` | id，软删除 | `system:user:delete` |
| GET | `/role/list` | 无参数 | `system:role:list` |
| GET | `/role/detail` | id，含 menuIds、permissionIds | `system:role:list` |
| POST | `/role/create` | name | `system:role:add` |
| POST | `/role/update` | id、name | `system:role:edit` |
| POST | `/role/delete` | id | `system:role:delete` |
| POST | `/role/permission` | id、menuIds、permissionIds，整体替换授权 | `system:role:permission` |
| GET | `/menu/list` | 无参数 | `system:menu:list` |
| GET | `/menu/tree` | 无参数，含按钮详情 | `system:menu:list` |
| POST | `/menu/create` | name、type；parentId/path/component/icon/sort 可选 | `system:menu:add` |
| POST | `/menu/update` | id，其他字段可选 | `system:menu:edit` |
| POST | `/menu/delete` | id | `system:menu:delete` |
| GET | `/menu/button/list` | menuId | `system:menu:list` |
| POST | `/menu/button/create` | menuId、permissionCode、name；sort 可选 | `system:menu:add` |
| POST | `/menu/button/update` | id、menuId、permissionCode、name；sort 可选 | `system:menu:edit` |
| POST | `/menu/button/delete` | id | `system:menu:delete` |
| GET | `/permission/list` | 无参数 | `system:permission:list` |
| POST | `/permission/create` | code、name | `system:permission:add` |
| POST | `/permission/update` | id、code、name | `system:permission:edit` |
| POST | `/permission/delete` | id | `system:permission:delete` |

用户 email、username、phone 唯一，手机号为 11 位国内手机号；软删除后仍保留这些唯一值。密码 8 至 72 字符，UTF-8 字节长度不超过 72。用户更新缺省字段不修改，`roleIds: []` 清空角色。

菜单 `type` 使用 `DIRECTORY` 或 `PAGE`，顶级 `parentId` 为 null。更新时不传 parentId 保留父级，显式 `parentId: null` 移到顶级。禁止将自身或子菜单设为父级。仍有子菜单、按钮或角色授权的菜单不能删除；仍有有效用户的角色不能删除。

按钮可绑定现有权限码，也可创建新权限码；一个权限只绑定一个按钮。删除按钮只删除绑定，保留权限和独立角色授权。权限仍被角色或按钮引用时不能删除。

## Swagger 与验证边界

默认关闭文档。本地可设置 `API_DOCS_ENABLED=true`，或使用启用文档的 local 示例，然后访问 `/swagger-ui/index.html`。接口文档使用 Bearer 认证。

自动化测试使用独立 H2 内存数据库的 PostgreSQL 兼容模式，执行 system 的 Flyway 脚本、实际 SQL、真实 HTTP、BCrypt 和 RSA JWT。覆盖 common 无数据库与安全配置的独立启动、原管理行为，以及两个真实服务间的身份共享、授权实时生效、401/403、管理路由隔离和统一服务故障时的 503。本机尚未连接独立 PostgreSQL 实例验证，打包通过不代表真实 PostgreSQL 环境已经启动成功。

保留原 Node 的返回、分页、权限码和菜单/按钮分离思路；Java 用户写操作改成 POST `/user/create`、`/user/update`、`/user/delete`，错误采用真实 HTTP 状态码。前端须同步这些路由和错误处理。微信登录、亲友借还款及前端管理页面属于后续业务。
