## 1. 确认规则与当前完成情况

已确认：家庭、生意业务完全独立；同一登录账号一本生意总账，不提供账套选择、成员共享或创建账套。生意使用 business schema、biz_ 表、/business/** 接口、business-service 模块、com.base.business 包。owner_id 只从已验证 Token 获取。界面切换不复制、同步两边数据。

当前后端仅有客户 create/update/delete/list/detail 五个接口；客户资料与当前未结款查询已有实现。现有买卖、结算表用于查询基础，尚无用户可操作的买卖、收付款、抵账写接口。商品、库存、费用、经营季查询、利润和首页汇总为规划。前端客户类型样式仍需实际验收，不能因为设计图存在就标记验收通过。

图中三类标记：`已有基础` 表示有对应代码或查询基础；`已确认·待开发` 表示需求确定但完整流程未落地；`建议·待定` 表示设计建议，不能直接作为已确认开发范围。

首页与账单的金额采用完整经营示例第4步（收粮后、抵账前）；客户列表另外展示正余额、负余额、净零待抵账与已结清等独立状态，不作为首页汇总的同一组客户数据。

## 2. 页面地图

### 首页：看经营概况

- 默认当前经营季，可切换历史季；当前应收、当前应付单独展示，不互相净掉。
- 本季销售收入、已售成本、销售毛利、经营费用、经营利润；收回旧欠款不重复计收入。
- 库存概览按产品和规格显示，不把所有化肥混成一个无法换算的袋数；粮食可同时显示斤和吨。
- 本季实际收款、付款及现金净变动；抵账不计现金。期初资金与本期收支分开。
- 快捷入口：卖化肥、收粮、化肥进货、卖粮、收款、付款、抵账、费用。
- 当前往来余额是所有经营季截至今日的未结余额。本季新增应收/应付与当前待结余额分开命名。
- 首页金额可进入相应明细；空数据展示 0 和录入入口，加载失败展示重试，不能用示例金额冒充真实业务。

### 客户：往来人管理

- 农户客户／商家客户两个 Tab，支持姓名和称谓搜索、分页、右下角新增。
- 固定两行布局：头像、姓名（称谓）、右侧净余额；第二行化肥和粮食剩余未结款，含正负号。
- 不增加村庄、最近往来日期或正负说明栏。正数珊瑚红，负数蓝色，两方向都保留数值符号。
- 应收、应付分别为零才显示已结清；净额为零但双向未结时显示“待抵账”。若同一商品类别也有双向未结，应在详情看到应收应付，不能仅凭类别净额判断结清。
- 农户可买化肥也可卖粮；商家可供化肥也可买粮，身份不限定交易方向。同一客户不按买入卖出重复建档。
- 详情：资料、分类净余额、总应收/总应付、买卖原单、收付款、抵账分配、经营季与历史时点。记录可钻取原单及结算详情。
- 列表左滑或长按修改/删除，详情也可修改。删除需确认；有任一未结应收或应付时阻止删除，保留所有历史。

### 账单：查业务流水

- 类型：全部、化肥进货、化肥销售、收粮、卖粮、收款、付款、抵账、费用。
- 筛选业务日期、客户、原单经营季、未结/部分结/已结/已作废。筛选控件可折叠，保持日常简洁。
- 买卖行分别展示原始成交金额、已结金额和剩余金额；收付款行展示实际收付；抵账行标记无现金。
- 结算可以结多笔，不能把每个分配明细再次算成一笔实际收付款。商品明细级分配可形成准确的类别余额。
- 撤销需查看依赖；已结算原单不能直接覆盖金额。关联结算、库存和成本冲销策略作为实施前待定项。

### 我的：资料与报表

- 商品分类、商品与规格、常用价格；资金账户；期初库存与成本；库存明细；经营季；经营报表；经营费用。
- 登录资料、设置沿用公共外壳，生意业务数据仍独立。家庭/生意切换只切入口。
- 不提供账套/生意成员入口。导出/备份、盘点和操作日志查看为建议扩展，不能默认已纳入本次开发。

## 3. 关键表单与操作

### 客户新增/修改（已有接口）

客户类型点选；姓名/名称必填；称谓、电话、备注选填。姓名最多30字，其他限制以现有接口为准。不能直接编辑余额。保存成功返回并刷新；失败保留已填内容。创建沿用 requestId 防重复提交。

### 商品（待开发）

分类化肥/粮食，名称、规格、基础计量单位、每袋千克数（袋装必填）、常用买入价/卖出价及其计价单位。买卖时可改成交价。名称、规格、单位、换算、价格快照保存进明细，后续修改商品档案不改变旧单。多种袋重不直接混加袋数。

### 四类买卖（待开发）

共用生意买卖录入能力，前台提供四个符合日常语言的入口：化肥进货、卖化肥、收粮、卖粮。它们均属于生意业务，不与家庭共用业务表或接口。

流程：选客户 → 选商品 → 自动带出单位/规格/常用价 → 输入数量 → 自动算金额 → 选择未收付/部分收付/全部收付 → 保存。支持一单多商品、从客户详情进入预选客户；保存后可继续记当前客户或换人。

业务日期和经营季默认当前，可在展开项调整。即时收付款必须选生意资金账户；未收付不出现账户必填。保存买卖单和即时结算时同事务生成原单及分配关系，不能在原单上直接减掉已付款。

化肥进货支持吨：1吨=1000千克，50千克/袋时1吨=20袋。销售支持袋。粮食收购支持市斤：1斤=0.5千克；销售支持吨。统一基础重量建议千克，精确小数计算。不可整袋时应提示规格/数量冲突；是否支持散装另定。

### 收款 / 付款（待开发）

客户、金额、实际日期、生意资金账户；默认仅选择对应方向的未结款，并按原单日期从早到晚分配，保存实际分配。可展开指定原单。部分支付只冲本次金额；跨季付款仍指向原季原单。禁止超出待结金额；预收预付和不分配收付款另列新需求，不默默生成负欠款。

### 抵账 / 抵账并付清（待开发）

同一客户同时存在应收应付时进入。展示两侧原单、本次抵账和抵后剩余。抵账金额不得超过两侧可结金额的较小值；必须确认，不能因为净额为0自动抵账。一张抵账单对两侧各分配同额；两侧金额不叠加为抵账发生额。

“抵账并付清”是组合操作：确认抵账500 + 实际付款700；后台同事务保存不同性质记录。若任一步失败，全部回滚。只抵账时不需要资金账户。客户不能跨人混抵。

### 费用（待开发）

经营日期、费用类别、金额、资金账户、经营季、备注；运费、装卸费等只影响生意。示例按当期经营费用核算。进货运费是否分摊库存成本及对应规则须单独确定，不能既资本化又重复扣费用。

## 4. 可核对的完整经营示例

以下均为示例。初始无库存、无欠款，生意账户期初资金10000元；期初资金不是营业收入。

| 步骤 | 操作 | 张三化肥未结 | 张三粮食未结 | 生意账户资金 | 化肥库存 | 小麦库存 | 累计毛利/经营利润 |
|---|---|---:|---:|---:|---:|---:|---:|
| 0 | 期初资金 | 0 | 0 | 10000 | 0袋 | 0斤 | 0/0 |
| 1 | 向李老板进化肥1吨，每袋50千克，20袋×80=1600；付1000，欠600 | 0 | 0 | 9000 | 20袋 | 0斤 | 0/0 |
| 2 | 张三买10袋×100=1000，未收钱；对应成本800 | +1000 | 0 | 9000 | 10袋 | 0斤 | 200/200 |
| 3 | 张三还500，分配到这笔化肥款 | +500 | 0 | 9500 | 10袋 | 0斤 | 200/200 |
| 4 | 收张三小麦1000斤×1.2=1200，未付 | +500 | -1200 | 9500 | 10袋 | 1000斤 | 200/200 |
| 5 | 双方确认抵账500 | 0 | -700 | 9500 | 10袋 | 1000斤 | 200/200 |
| 6 | 实际付张三700 | 0 | 0 | 8800 | 10袋 | 1000斤 | 200/200 |
| 7 | 小麦0.5吨×2600元/吨=1300卖给粮商，当场收齐；对应成本1200 | 0 | 0 | 10100 | 10袋 | 0斤 | 300/300 |
| 8 | 支付当期经营费用100 | 0 | 0 | 10000 | 10袋 | 0斤 | 300/200 |

期末：张三全部结清；仍欠供应商600；化肥剩10袋、成本800；销售收入2300，已售成本2000，毛利300，费用100，经营利润200。现金净变动0，不能据此认为没赚钱。

核对：资金10000 + 库存成本800 - 应付600 = 期初净资产10000 + 利润200（此简化示例无其他资产负债及投入提取）。

净零反例：化肥+600、粮食-600时，应收600、应付600，状态待抵账；确认抵账600以后，才是应收0、应付0、已结清。

## 5. 库存、成本与跨季

- 买入增加库存和库存成本；卖出减少库存并结转对应成本；收付款与抵账不改库存，不重复确认销售利润。
- 成本算法尚未确定：先进先出或移动加权平均需实施前选定，图中不把FIFO当成已确认。示例每种商品只有一批，因此两算法结果一致。
- 初始化库存应录数量、成本和启用日，不生成虚假采购付款。历史应收应付如何初始化须另定可追溯方案，不混入本季销售或重复复制欠款。
- 跨季保留相同库存与成本来源，不清零、不重新进货；欠款仍关联旧原单。新季展示历史结余只做计算，不生成新欠款。
- 业务日期、原单经营季、实际结算日期分开。查2026麦季末时，只计截止当时有效结算；2026秋季还麦季欠款计入秋季现金，但不增加秋季销售收入。
- 是否封账、封账后补录及撤销的生效口径需要另定。当前不默认强制封账，不把历史时点计算等同不可修改的会计快照。
- 负库存、退货、损耗、盘盈盘亏、质量扣量、抹零、优惠、预收预付的具体规则均为扩展待定。建议首版阻止超库存销售及超额核销，异常明确提示。

## 6. 后端数据关系与接口落点

已有实体及查询基础：biz_customer、biz_trade、biz_trade_item、biz_settlement、biz_settlement_item。所有业务行归属owner_id，关联校验同一账号/客户。

关系：客户1:N买卖；买卖1:N商品明细；结算1:N分配；商品明细1:N分配，形成买卖与结算多对多。抵账分别分配到sale和purchase两侧，单边合计各等于amount_cents。

待建：biz_product_category、biz_product，以及资金账户/资金流水、库存变动/成本来源、费用等表。具体字段、约束和索引在对应阶段设计，不在本稿改建或迁移数据库。经营季可先保存标签，是否建独立表另定。

| 能力 | 接口（除客户外均为规划） |
|---|---|
| 客户 | /business/customer/create、update、delete、list、detail（已有） |
| 商品 | /business/product/**、/business/product-category/** |
| 买卖 | /business/trade/create、list、detail（规划） |
| 结算 | /business/settlement/create、list、detail（规划） |
| 库存/资金/费用 | /business/inventory/**、/business/account/**、/business/expense/** |
| 统计 | /business/statistics/summary 等（规划） |

金额整数分，数量和单价精确小数，统一后端舍入；明细舍入与总金额汇总口径须统一。保存、分配、库存、成本、现金变动在同一事务；requestId幂等、账号/客户及必要库存行锁、并发重算、关联归属检查。不能依赖页面禁用按钮作为唯一约束。

删除客户沿用软删除及应收应付分别校验。修改或撤销已结算交易应校验依赖并留痕，具体冲销方式待实施确认。已执行Flyway脚本保留；新迁移单独增量登记。停用business.enabled后家庭接口及启动不依赖生意初始化。

## 7. 分阶段交付与验收

1. 验收现有客户页面与样式；商品、规格、单位、换算与常用价格。
2. 打通卖化肥、收粮、实际收付款、抵账、客户往来及原单/结算明细。
3. 补齐化肥进货、卖粮、期初库存与成本、进出库和选定的成本算法。
4. 经营费用、经营季与历史余额、利润、现金及首页汇总。

页面可以分期开发；正式启用库存成本前需设计启用日和期初衔接，不能把早期未记录库存的买卖直接算成零成本。

每期验证跨账号访问拒绝、同家庭不共享、重复请求、并发、失败回滚、历史保留。核心验收链：卖化肥1000→收500→收粮1200→抵500→付700；每一步核对张三应收/应付与现金，抵账不生成现金，原单始终保留。补充净额0仍待抵账、跨季还款、商品价格改动不改旧单、业务停用后家庭可用。真实PostgreSQL迁移和微信真机验收仍属于后续交付检查。
