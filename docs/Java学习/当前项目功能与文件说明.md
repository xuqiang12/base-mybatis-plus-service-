更新日期：2026-10-13。已按统一账号权限拆成四模块、两个运行服务；本次通过隔离数据库和真实 HTTP 验证，未连接实际 PostgreSQL。

## 第一步：知道项目目前做到了哪里

当前工程已经具备统一用户与权限管理后端，并能为亲友服务提供实时身份授权。管理接口在 system，亲友服务仅提供健康检查及后续业务入口。

| 已有功能 | 可以做什么 |
| --- | --- |
| 服务启动和健康检查 | 启动 Spring Boot，通过 `GET /health` 确认 HTTP 服务响应 |
| 登录和注册 | 邮箱、密码登录；公开注册普通用户；登录返回 JWT Token |
| 当前用户信息 | 返回当前用户、操作权限和可见菜单 |
| 用户管理 | 分页、条件查询、详情、新增、修改、软删除、分配角色 |
| 角色管理 | 查询、新增、修改、删除；分别给角色分配菜单与操作权限 |
| 菜单管理 | 菜单列表、树结构、父子关系、新增、修改、删除 |
| 按钮管理 | 维护菜单下的按钮，把按钮与权限码关联 |
| 权限码管理 | 查询、新增、修改、删除操作权限，例如 `system:user:list` |
| 基础请求处理 | 统一返回、参数校验、错误处理、请求日志、分页、时间格式 |
| 数据库结构初始化 | PostgreSQL 配置与 Flyway 建表脚本；创建 8 张应用表、18 个初始操作权限 |
| 管理员初始化 | 显式提供配置且用户表为空时创建首位超级管理员 |
| 接口文档和测试 | Swagger 文档配置；HTTP、认证、授权、数据库、事务与并发测试 |

尚未实现：亲友资料、借款、还款、人情往来、微信登录、前端管理页面。

## 第二步：理解四个模块的关系

```text
父工程（根 pom.xml）
  ├─ base-common：公共类库，提供通用 HTTP 基础，不启动
  ├─ base-security：安全类库，依赖 common，不启动
  ├─ system-service：统一管理服务，依赖 security，独立启动在 8080
  └─ relations-service：亲友服务，依赖 security，独立启动在 8081
```

common 和 security 没有自己的 main，也不单独占端口。两个服务将公共类库打进自己的运行包；system 维护身份权限数据，relations 通过 HTTP 查询 system 的当前授权。

启动关系：各服务 Application → SpringApplication.run → 导入 BaseSecurityConfiguration → 导入 BaseCommonConfiguration。服务扫描自身业务包；system 提供本地 AccessService，relations 提供远程 RemoteCurrentUserProvider。

注意：com.base.common、security、system、relations 是同级包。启动类默认只扫描自身包及子包，不能为了加载公共代码直接扫描整个 com.base，否则可能把其他服务一起加载。

## 第三步：先认识文件类型

| 名称 | 通俗解释 | 当前例子 |
| --- | --- | --- |
| Controller | 接收接口请求，调用业务逻辑 | `UserController` |
| Service | 实现业务规则，例如检查角色、处理密码 | `UserService` |
| Mapper | 向数据库发起查询、新增、修改、删除 | `UserMapper` |
| Entity | Java 中表示数据库表字段的对象 | `UserEntity` |
| Request DTO | 定义客户端能传哪些字段、字段是否合法 | `UserRequests` |
| Response DTO | 定义返回给客户端哪些字段 | `UserResponse` |
| Config / Configuration | 注册和设置框架组件 | `SecurityConfig` |
| Filter / Advice / Handler | 处理多个接口共用的日志、响应、错误 | `RequestLogFilter`、`ResponseAdvice` |

当前基础 Mapper 继承 MyBatis-Plus 的 `BaseMapper`，因此可以直接使用 `selectById`、`insert` 等方法。关联 SQL 写在 `AccessMapper` 的注解里，目前没有自定义 Mapper XML 文件，也没有独立的 `ServiceImpl`。

## 第五步：沿一条实际请求读代码

以 `GET /user/list?pageNum=1&pageSize=10` 为例：

1. `RequestLogFilter` 开始计时。
2. `SecurityConfig` 校验 Bearer Token，`AccessService` 查询当前用户与最新权限。
3. `UserController.list()` 检查查看用户列表的权限，读取并校验 `UserRequests.ListQuery`。
4. `UserService.list()` 组装筛选条件和分页参数。
5. `UserMapper.selectPage()` 通过 MyBatis-Plus 查询 `relations.sys_user`。
6. `UserService` 将结果转为不含密码的 `UserResponse`，放入 `PageResult`。
7. `ResponseAdvice` 包装为 ApiResponse，`JacksonConfig` 参与时间序列化。
8. 返回 JSON；日志过滤器记录状态与耗时。发生错误时，由安全错误处理器或全局异常处理器返回统一错误。

因此，查一个功能时先看 Controller 路由，再进入 Service，最后找 Mapper 和 Entity。IDEA 的 `Ctrl+B` 可以跳到声明或方法定义。
