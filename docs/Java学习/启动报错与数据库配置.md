# 启动报错与数据库配置

> 多服务拆分后的入口更新：本文保留原排查和 Neon 学习记录。当前数据库配置归 `system-service/src/main/resources/application-local.yml`，启动类为 `SystemApplication`；relations 不再连接身份权限数据库。旧 JWT_SECRET 步骤替换为 [基础规范与运行说明](../基础规范与运行说明.md) 中的 RSA 密钥配置，不要把数据库或私钥放到 relations。以下历史日志中的 RelationsApplication 是拆分前的入口。

记录日期：2026-10-13。状态：本机 Neon 配置已完成，Java JDBC 只读连接验证成功；当前项目已拆分为两个服务，数据库由 system-service 管理，应用启动与建表尚未验证。

## 第一步：找到真正的错误

本次 IDEA 运行日志的关键内容：

```text
Connection to localhost:5432 refused
Caused by: java.net.ConnectException: Connection refused
```

意思：程序尝试连接本机 5432 端口的 PostgreSQL，但连接被拒绝，尚未进入用户名密码校验阶段。

Java 21 已正常启动，Spring Boot 开始加载，随后数据库初始化失败，Tomcat 停止，进程退出码为 1。日志出现 Tomcat initialized 不代表整个后端已启动成功。

## 第二步：知道为什么启动就连接数据库

当前 `application.yml` 的默认地址为 `jdbc:postgresql://localhost:5432/relations`。

启动过程：Flyway 连接数据库并执行迁移 → MyBatis 初始化 Mapper → 加载依赖 Mapper 的用户、权限等服务。

数据库连接失败会使这条依赖链整体失败，因此日志最上方虽然提到 `accessService`、`userMapper`，根因仍是数据库连接被拒绝。

## 第三步：本次排查结果

1. 本机 5432 端口没有监听。
2. 未在 Windows 服务列表和检查的常见安装目录中发现 PostgreSQL，也没有找到 PATH 中的 psql/pg_ctl。此检查不能排除其他目录、Docker 或远程数据库。
3. IDEA 保存的运行配置没有显式启用 local 环境，也没有显式配置数据库环境变量；未发现 `application-local.yml`。
4. 当前代码还要求配置 JWT 密钥；该项不是本次日志中的根因，准备运行环境时也要配置。
5. 你反馈数据库已安装在本机或 Docker 中。后续检查找到 Docker 命令，但执行 `docker ps -a` 提示 `dockerDesktopLinuxEngine` 管道不存在，说明当前 Docker Linux 引擎不可连接，暂时无法列出数据库容器。
6. 进一步查看当前项目旁的 `F:\公司项目\gitee\nestjs-prisma`：Node 的 Prisma 源码和本机已生成的 Prisma Client 都使用 `NEON_DATABASE_URL`、`NEON_DIRECT_URL`；本机 `.env` 已配置 Neon 云端连接，要求 SSL。本次未输出或记录真实连接地址、账号、密码，也未连接远程数据库。

## 第四步：下一步操作

先确认你准备使用本机安装、Docker 还是远程 PostgreSQL，再按实际情况逐步操作：

上一轮建议检查 Docker，是排查本机数据库的分支。核对 Node 配置后，确认其使用 Neon 云端 PostgreSQL，因此运行该 Node 配置无需本机 PostgreSQL 容器。下一步先确定 Java 也使用 Neon，还是另外准备本机数据库，再配置对应地址。

1. 使 PostgreSQL 在正确地址和端口上可连接。
2. 准备独立的 relations 数据库和有建表权限的账户。
3. 在本机配置或 IDEA 环境变量里填写数据库地址、账户、密码和 JWT 密钥。
4. 重新运行，检查 `Started RelationsApplication`，再访问 `/health`。

验收状态：以上操作待执行。具体点击步骤根据实际数据库环境补充，不记录密码或密钥。

测试曾通过的原因：集成测试使用独立的 H2 内存数据库；IDEA 正常运行使用 PostgreSQL，两者运行环境不同。

## 第五步：Node 的数据库连接方式

连接链：Node 项目的 `.env` → `prisma/schema.prisma` → `PrismaService` → Neon 云端 PostgreSQL。

| 文件或配置 | 用途 |
| --- | --- |
| Node 的 `.env` | 保存 `NEON_DATABASE_URL`（应用连接池地址）和 `NEON_DIRECT_URL`（迁移等操作使用的直连地址） |
| Node 的 `prisma/schema.prisma` | `provider = "postgresql"`，url 读取 NEON_DATABASE_URL，directUrl 读取 NEON_DIRECT_URL；LOCAL_DATABASE_URL 两行当前被注释 |
| Node 的 `src/app.module.ts` | ConfigModule 加载环境配置，PrismaModule 注册全局 PrismaService |
| Node 的 `src/modules/user/user.service.ts` | 注入 PrismaService，调用 `prisma.user.findMany` 等方法操作数据库 |
| Java 的 `application.yml` | 读取 DB_URL、DB_USERNAME、DB_PASSWORD；未配置地址时连接 localhost:5432/relations |

Prisma 的 PostgreSQL URL 与 Java JDBC 配置格式不同。若后续让 Java 接入 Neon，需要把地址转换成 JDBC URL，把用户名、密码分别配置，并启用 SSL；不能把 Prisma 完整连接串直接填进 DB_URL。

Java 的 Flyway 会创建自己的 `relations` schema 和基础表。连接云端数据库之前需确认目标数据库及建表权限，并继续使用独立 schema；本次只分析，没有修改连接配置，也没有执行建表或迁移。

核验范围：源码、本机环境文件的连接类型和本机生成的 Prisma Client；未验证 Neon 当前连通性、云端运行配置或账户建表权限。

## 第六步：让 Java 也连接 Neon

本节前面的手动步骤记录的是拆分前的配置过程。当前有效配置和运行方式见下面第七步；当前使用 RSA 公私钥，不再配置 JWT_SECRET。

你已选择沿用 Neon 云端 PostgreSQL。Java 使用独立的 `relations` schema，沿用当前 Flyway 配置；数据库管理员权限是否允许建 schema、现有 relations schema 是否已有表，需要在实际运行前确认。

1. 先准备本机文件：在 IDEA 的 `relations-service/src/main/resources` 中选中 `application-local.example.yml`，按 `Ctrl+C`、`Ctrl+V`，复制文件命名为 `application-local.yml`。该文件已被 Git 忽略，用于保存本机配置。
2. 填写数据库配置：参考 Node `.env` 的 `NEON_DIRECT_URL`，分别取出主机、数据库名、用户名和密码。Java 的 url 格式为 `jdbc:postgresql://<主机>:5432/<数据库名>?sslmode=require`，用户名和密码分别填到 username、password，字符串建议加双引号。若原连接使用其他端口，保留实际端口；URL 中编码过的用户名和密码要先解码。此文档只保存格式，不记录真实连接信息。
3. 配置 JWT_SECRET：为 Java 准备独立的随机密钥，至少 32 字符，填入 IDEA 运行配置的环境变量；模板会通过 `${JWT_SECRET:}` 读取。具体生成步骤在学到此处时补充。
4. 启用本机配置：在「运行 → 编辑配置 → RelationsApplication → 程序参数」中填 `--spring.profiles.active=local`。
5. 配置完成后再运行，观察数据库连接、Flyway 迁移和 Spring Boot 启动结果，再验证 `/health`。首次运行会尝试创建 relations schema 及其基础表。

当前学习进度：先由你完成第 1 项文件复制；其余配置与运行待操作。本轮仅更新教学记录，没有代填凭据或启动数据库迁移。

## 第七步：当前两个服务的本机配置与运行

你已授权根据 Node 项目填写 Java 本机配置，以下配置已完成：

| 本机文件 | 配置内容 |
| --- | --- |
| `system-service/src/main/resources/application-local.yml` | 从 Node 的 NEON_DIRECT_URL 提取数据库地址、用户名和密码；转换为 JDBC URL，配置 sslmode=require；读取本机 RSA 公钥和私钥 |
| `relations-service/src/main/resources/application-local.yml` | 读取同一 RSA 公钥；通过 localhost:8080/auth/access 访问统一管理服务，不配置身份数据库或私钥 |
| `config/jwt-private.pem` | 本机生成的 2048 位 RSA 私钥，仅供 system-service 签发 Token |
| `config/jwt-public.pem` | 与私钥匹配的 RSA 公钥，两个服务均用它验证 Token |
| `.run/SystemApplication-local.run.xml` | IDEA 运行项，启动统一管理服务并启用 local 配置 |
| `.run/RelationsApplication-local.run.xml` | IDEA 运行项，启动亲友服务并启用 local 配置 |

本机配置与密钥均已验证被 Git 忽略，运行项不含密码和密钥。现有管理员初始化配置保留，没有自动填写管理员账户或密码。

验证结果：两个本机文件 YAML 结构正确、公私钥配对成功；Java 21 的 PostgreSQL JDBC 驱动已成功连接 Neon，并执行只读查询。目标数据库当前不存在 relations schema，账户具有创建 schema 的权限。没有执行 Flyway、建表、初始化用户或修改 Node 数据。

下一步由你在 IDEA 操作：

1. 点击右上角运行配置下拉框，选择 `SystemApplication-local`，点击运行；默认 8080。也可在 `.run` 目录打开对应运行配置文件，右键运行。
2. 首次启动会由 Flyway 创建 relations schema 和基础表。观察控制台是否出现 `Started SystemApplication`，再访问 `http://localhost:8080/health`。
3. 再选择 `RelationsApplication-local` 运行，默认 8081，访问 `http://localhost:8081/health`。
4. 本机接口文档地址为 `http://localhost:8080/swagger-ui/index.html`。

应用启动和迁移结果待你的实际运行确认。登录前需另行确认是否初始化首位管理员，或通过公开注册创建普通用户。

## 第八步：用接口检查服务是否启动

1. 在浏览器打开 `http://localhost:8081/health`，检查亲友服务。
2. 成功时返回：`{"code":0,"message":"success","data":{"status":"UP","service":"relations-service"}}`，JSON 字段顺序可能不同。
3. 若要检查统一管理服务，先在 IDEA 选择 `SystemApplication-local` 并运行，再打开 `http://localhost:8080/health`。
4. 统一管理服务启动后，打开 `http://localhost:8080/swagger-ui/index.html` 查看接口文档。

2026-10-13 实测：8081 的 `/health` 返回 HTTP 200；8080 的 `/health` 暂时无法连接。`/health` 只确认服务能响应 HTTP 请求，数据库迁移、登录和跨服务权限调用需分别验证。
