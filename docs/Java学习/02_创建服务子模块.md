# 02 创建服务子模块

> 本文保留当时的手写和重建练习记录，不是当前工程重建脚本。当前根工程登记 common、security、relations、system 四个模块；relations 依赖 security，system 还在测试范围引用 relations，不能直接删除 relations 后照旧构建。新建无认证服务可引用 common 并导入公共入口；需要认证时使用 security 和身份提供实现，参见 [统一账号多服务设计](../统一账号多服务设计.md)。无需重新执行下文的删除步骤。

记录日期：2026-10-13。状态：模块、Web 依赖、包和空类已创建，启动代码待补充。

## 目的与前提

假设 `relations-service` 文件夹已经删除，根 `pom.xml` 和 `base-common` 仍保留，学习如何重新创建一个能独立启动的服务。本教程未执行删除或重建。

创建流程：建 Maven 模块 → 配置父工程和依赖 → 写启动类 → 写接口 → 运行验证。

## 第一步：在 IDEA 新建 Maven 模块

1. 打开整个 `base-mybatis-plus-service` 项目。
2. 点击「文件 → 新建 → 模块」。
3. 选择 Java，构建系统选 Maven，JDK 选 21。旧版 IDEA 可能直接显示 Maven 选项。
4. 名称填 `relations-service`，模块最终目录确认是：

   ```text
   F:\公司项目\gitee\base-mybatis-plus-service\relations-service
   ```

5. 父项选择 `base-mybatis-plus-service`。展开「高级设置」：组 ID 填 `com.base`，工件 ID 填 `relations-service`；如果有 Version 输入框，填 `0.0.1-SNAPSHOT`。
6. 取消勾选「添加示例代码」，点击「创建」。

成功标志：项目根目录下出现 `relations-service`，里面有 `pom.xml`。

## 第二步：在父工程登记模块

打开根目录的 `pom.xml`，确认有以下内容：

```xml
<modules>
    <module>base-common</module>
    <module>relations-service</module>
</modules>
```

已有 `relations-service` 这一行就保留，不要重复添加。删除文件夹后如果暂时提示找不到模块，重新创建目录即可恢复对应关系。

作用：告诉 Maven 构建整个工程时包含哪些模块。

## 第三步：配置子模块的 pom.xml

分步学习时，当前先在 `relations-service/pom.xml` 的 `</project>` 前添加下面这一段，保留 IDEA 已生成的其他内容：

```xml
<dependencies>
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-web</artifactId>
    </dependency>
</dependencies>
```

保存后，在 Maven 面板点击左上角刷新按钮，等待加载完成。成功标志：依赖加载完成，没有下载失败或依赖解析错误。

作用：让模块具备提供 HTTP 接口的依赖。版本由父工程管理，这里不用填写 `version`。

下面是后续加入公共类库、测试依赖和打包插件后的完整参考配置，按学习进度逐项添加：

```xml
<project xmlns="http://maven.apache.org/POM/4.0.0"
         xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="http://maven.apache.org/POM/4.0.0 https://maven.apache.org/xsd/maven-4.0.0.xsd">
    <modelVersion>4.0.0</modelVersion>

    <parent>
        <groupId>com.base</groupId>
        <artifactId>base-mybatis-plus-service</artifactId>
        <version>0.0.1-SNAPSHOT</version>
    </parent>

    <artifactId>relations-service</artifactId>

    <dependencies>
        <dependency>
            <groupId>com.base</groupId>
            <artifactId>base-common</artifactId>
            <version>${project.version}</version>
        </dependency>
        <dependency>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-starter-web</artifactId>
        </dependency>
        <dependency>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-starter-test</artifactId>
            <scope>test</scope>
        </dependency>
    </dependencies>

    <build>
        <plugins>
            <plugin>
                <groupId>org.springframework.boot</groupId>
                <artifactId>spring-boot-maven-plugin</artifactId>
            </plugin>
        </plugins>
    </build>
</project>
```

只记住四件事：

- `parent`：继承现有父工程，复用 Java 和依赖版本配置；默认从 `../pom.xml` 查找父工程。
- `base-common`：使用已有的统一返回类。
- `spring-boot-starter-web`：提供 HTTP 服务所需的依赖。
- `spring-boot-maven-plugin`：将服务打成可执行 JAR；测试依赖供后续写测试使用。

点击 Maven 面板的「重新加载所有 Maven 项目」，等待完成。

## 第四步：创建启动类

在 `relations-service/src/main/java` 上右键 →「新建 → 包」，输入 `com.base.relations`。

在该包上右键 →「新建 → Java 类」，输入 `RelationsApplication`。

### 在 IDEA 中手写：输入什么、提示什么、选择哪个

按小步骤操作，每一步确认后再继续。

1. 写启动注解：在 `public class RelationsApplication` 上方新起一行，输入 `@SpringBoot`。补全列表中选择 `SpringBootApplication`，所属包是 `org.springframework.boot.autoconfigure`，按回车。IDEA 通常会自动添加对应的 `import`；若类名仍红，光标放在名称上按 `Alt+Enter`，选择导入该类。成功标志：类上方是 `@SpringBootApplication`，没有红色未解析提示。
2. 写入口方法：将光标放到类的 `{ }` 内，输入 `main`，选择表示「main 方法声明」的实时模板（界面描述可能不同），按回车或 Tab 展开。也可以输入 `psvm` 后按 Tab。IDEA 生成 `public static void main(String[] args)` 及方法体，把光标放进方法体。`main` 是 Java 程序入口，`psvm` 是 IDEA 的模板缩写。
3. 写启动语句：在 `main` 方法体内输入 `SpringApp`，选择 `SpringApplication`，所属包是 `org.springframework.boot`；输入 `.run`，选择首个参数为 `Class<?> primarySource` 的 `run` 方法。在括号内输入 `RelationsApplication.class, args`，语句末尾添加英文分号 `;`。这行告诉 Spring Boot 使用当前类启动服务，并传入启动参数。确认两个 Spring 类的导入都存在、没有红色报错，再运行。

如果没有补全列表，按 `Ctrl+Space` 尝试打开；若快捷键被输入法占用，先切换英文输入法。菜单与说明不一致时，先发当前补全列表截图，再选择。

完整代码作为对照：

```java
package com.base.relations;

import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;

// 启动服务，扫描当前包及子包中的组件。
@SpringBootApplication
public class RelationsApplication {

    // Java 程序的启动入口。
    public static void main(String[] args) {
        SpringApplication.run(RelationsApplication.class, args);
    }
}
```

如果没有 `src/main/java`，在模块目录上右键 →「新建 → 目录」，创建该路径，然后重新加载 Maven。

## 第五步：创建一个验证接口

在 `src/main/java` 下新建包 `com.base.relations.controller`，在包里新建类 `HealthController`：

```java
package com.base.relations.controller;

import com.base.common.result.ApiResponse;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RestController;

import java.util.Map;

// 接收 HTTP 请求并返回数据。
@RestController
public class HealthController {

    // 浏览器访问 /health 时执行此方法。
    @GetMapping("/health")
    public ApiResponse<Map<String, String>> health() {
        return ApiResponse.success(Map.of("service", "relations-service", "status", "UP"));
    }
}
```

Controller 放在启动类所在包的子包下，Spring Boot 默认才能扫描到它。

## 第六步：创建服务配置

在 `relations-service/src/main/resources` 上右键 →「新建 → 文件」，命名 `application.yml`：

```yaml
spring:
  application:
    name: relations-service

server:
  port: 8080
```

如果没有 `src/main/resources`，先创建该目录。YAML 按示例使用空格缩进。

## 第七步：运行并验收

1. 点击 `RelationsApplication.main()` 左侧绿色三角形运行。
2. 控制台出现 `Started RelationsApplication`。
3. 浏览器访问 `http://localhost:8080/health`。
4. 返回 `code: 0`，且 `data` 中有 `service: "relations-service"`、`status: "UP"`，说明新服务可以响应请求。

这一步只验证启动和接口。原模块删除前的测试文件不会自动恢复；后续学习测试时再编写。

## 创建其他服务时改哪些地方

例如创建 `order-service`：模块目录、子模块 `artifactId`、父工程的 `module` 都改为 `order-service`；包名用 `com.base.order`，启动类用 `OrderApplication`，配置中的服务名和接口返回的服务名也相应修改。

同时运行多个服务时，每个服务使用不同端口，例如 `8080`、`8081`。

## 重建前：如何删除旧模块

以下步骤会删除 `relations-service` 的源码、配置和测试文件。需要保留的文件先复制到项目外；当前这些文件尚未被 Git 跟踪，不能依赖 Git 恢复。

1. 如果服务正在运行，先点击 IDEA 运行窗口中的红色停止按钮。
2. 打开项目根目录的 `pom.xml`，删除 `<module>relations-service</module>` 这一行，保留 `base-common`。删除后应为：

   ```xml
   <modules>
       <module>base-common</module>
   </modules>
   ```

3. 在 IDEA 左侧右键 `relations-service` →「移除模块」，在弹窗中点击「移除」。这一步只解除 IDEA 的模块关联，弹窗会说明「将不会删除文件」。
4. 再次右键左侧的 `relations-service` 文件夹，此时菜单中会出现「删除」，点击并确认，删除磁盘上的文件夹。
5. 点击 Maven 面板的「重新加载所有 Maven 项目」。

记忆顺序：先移除模块 → 再次右键 → 删除文件夹。这是你在当前 IDEA 中实际操作成功的方式。

成功标志：磁盘中已没有 `relations-service` 文件夹，根 `pom.xml` 的 `modules` 中也没有它，Maven 重新加载不再提示找不到该模块。

如果右上角还保留旧的 `RelationsApplication` 运行配置，可在「运行 → 编辑配置」中选中它，点击减号移除。

重新创建时，按本文第一步开始，并在根 `pom.xml` 的 `modules` 中重新加回 `relations-service`。
