# 03 包名含义与命名规范

记录日期：2026-10-13。状态：概念已讲解，已创建 `com.base.relations` 包和 `RelationsApplication` 空类，包声明与路径已核对。

## 第一步：认识包名

Java 的包（package）用于组织代码、区分同名的类。在当前 Maven 项目中，包名通常对应 `src/main/java` 下的目录结构。

`com.base.relations` 的含义：

| 部分 | 含义 |
| --- | --- |
| `com` | 常见域名后缀，来自域名倒写的命名惯例 |
| `base` | 当前基础工程采用的名称，与已有 `com.base.common` 保持统一 |
| `relations` | 亲友往来业务模块的名称 |

`com.base` 是这个学习项目现有的统一前缀，不表示已经拥有 `base.com` 域名。

## 第二步：记住命名规则

1. 常用惯例是「倒写域名 + 项目或业务名称」。例如拥有 `example.com` 的组织，可以用 `com.example.relations`。
2. 包名通常全部使用小写英文，例如 `com.base.relations.controller`。
3. 用点分隔各段；每段须是合法 Java 标识符，不能有空格、短横线，不能以数字开头，也不能使用 Java 关键字。
4. 同一工程的业务包保持统一前缀，例如 `com.base.relations`、`com.base.order`。

全小写和倒写域名属于命名惯例，合法标识符属于语法要求。学习项目可以沿用现有前缀。

## 第三步：区分三个名称

| 名称 | 示例 | 作用 |
| --- | --- | --- |
| Maven 模块名 | `relations-service` | 标识构建模块，可以包含短横线 |
| Java 包名 | `com.base.relations` | 组织 Java 类，不能包含短横线 |
| Java 类名 | `RelationsApplication` | 标识一个类，通常使用首字母大写的驼峰命名 |

Maven 的 GroupId 是依赖坐标的一部分，Java 包名是源码的一部分。当前都使用 `com.base` 前缀便于统一，但 Java 不要求两者必须相同。

## 第四步：在 IDEA 中创建

右键 `relations-service/src/main/java` →「新建 → 包」→ 输入 `com.base.relations`。

对应文件路径：`src/main/java/com/base/relations/RelationsApplication.java`。

该类开头写 `package com.base.relations;`，表示它属于这个包。IDEA 可能把多层目录合并显示成 `com.base.relations`，这是正常的显示方式。

当前把启动类放在 `com.base.relations`，后续 Controller 放在 `com.base.relations.controller`，默认能被 `@SpringBootApplication` 扫描到。

成功标志：IDEA 中出现该包，在其中创建 Java 类时，文件开头自动带有正确的 `package` 声明。
