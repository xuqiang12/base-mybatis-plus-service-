# 微信家庭邀请实施计划

依据：2026-10-19 用户确认的分享卡片方案，直接在两个现有工作目录实施，保留已有未提交改动。

1. 替换家庭 HTTP 测试为签名分享邀请：分享、读取、加入、退出、篡改、登录凭证隔离和并发加入。先运行观察旧实现失败。
2. 后端复用 JWT 签名和验签，邀请使用独立 subject，携带邀请者和原家庭 ID，不设定时过期。删除随机码、邀请持久化、状态、查询及快照邀请字段；保留家庭事务和成员校验。
3. 小程序家庭页直接通过微信分享按钮发送卡片，从卡片进入后登录并返回原邀请，显示邀请者与确认加入。删除手动生成、复制、输入及本机模拟邀请/合并流程，保留本机账目与示例浏览。
4. 更新对应 API、Store、类型、mock、测试和当前文档；SQL 已执行历史迁移原文保留，不执行业务数据库清理。
5. 验证：后端 Maven clean verify；小程序全部 Node 测试、变更文件 lint、微信小程序构建；搜索旧业务符号并检查 diff。微信真实转发与双账号真机操作另需设备验证。

接口契约：POST /family/invitation/share 返回 {token}；GET /family/invitation?token= 返回 {familyName,inviterName}；POST /family/invitation/accept 接收 {token}。所有接口要求登录，写请求继续携带 X-Family-Id。

卡片链接可转发，首位符合条件且确认的人加入；成功后双方迁入新家庭，原家庭邀请自然失效。无撤销、倒计时、历史合并及账目复制功能。
