# 系统初始化与新库使用

## 当前方式

初始化已独立为 Maven 模块 `database-seed`。默认数据是 JSON，Java 读取 JSON 并在事务内写入数据库；文件全部归属该模块，按服务分目录，不按版本拆 JSON 文件夹。

- 日常启动 `SystemApplication-local`：提供业务接口，不执行系统 Seed，也不再自动创建管理员。
- 需要初始化时运行 `SeedApplication-local`：先检查/执行 Flyway 迁移，再执行未完成的 Seed，关闭连接池并退出，不监听 HTTP 端口。
- Flyway 的历史 SQL 仍归根目录 `sql/`，保留已执行脚本与校验和。历史脚本中的权限/菜单初始化仍随首次迁移执行；独立 Seed 处理当前默认值与管理员。

当前已实现系统权限初始化。首页装修、底部导航、AI 以及阿里云用户账本导入均不在本次范围。当前本机连接仍使用 `gift_ledger`，schema 为 `relations`。

## 文件布局

```text
database-seed/
├── pom.xml
├── README.md
├── seed.ps1                              可选终端快捷入口
└── src/
    ├── main/
    │   ├── java/com/base/seed/
    │   │   ├── SeedApplication.java          独立入口，执行后退出
    │   │   ├── SeedRunner.java               启动时调用初始化
    │   │   ├── SystemSeedService.java        匹配、写入、事务与执行历史
    │   │   └── SeedAdminProperties.java      首次管理员配置
    │   └── resources/
    │       ├── database-seed.yml             无 Web 的默认配置
    │       ├── application-local.example.yml
    │       └── seeds/system-service/
    │           ├── permissions.json
    │           ├── menus.json
    │           ├── buttons.json
    │           └── roles.json               包含角色菜单/权限的默认关联
    └── test/                                隔离 H2 集成测试
```

`database-seed` 依赖 `system-service` 的普通 JAR，仅用于复用同一套 SQL 和 Java Flyway 迁移。组件扫描限定在 `com.base.seed`，不加载业务服务、Controller 或 JWT 配置。业务模块不依赖初始化模块。

## IDEA 怎么点

1. Maven 面板点击“重新加载所有 Maven 项目”，项目树会出现 `database-seed`。
2. 顶部运行配置下拉框选择 **SeedApplication-local**。
3. 确认本机配置里的数据库地址和 `app.seed-admin`，点击绿色运行按钮。
4. 控制台看到“数据库初始化完成”，随后进程退出即执行完成。再次运行会跳过已完成版本。
5. 开发业务时切回 **SystemApplication-local**。

运行配置在 `.run/SeedApplication-local.run.xml`，复用现有 `system-service/src/main/resources/application-local.yml`，不重复保存真实凭证。Seed 只需要其中数据库和 `app.seed-admin`，不需要邮箱或 JWT 密钥。

新环境也可从 `database-seed/src/main/resources/application-local.example.yml` 复制本机文件，修改 Seed 运行配置的 `spring.config.additional-location` 指向该文件。文件被 Git 忽略且不打入 JAR。

首次创建管理员需要：

```yaml
app:
  seed-admin:
    username: administrator
    email: "你的管理员邮箱"
    password: "你的初始密码"
```

也支持 `DB_URL`、`DB_USERNAME`、`DB_PASSWORD` 和 `SEED_ADMIN_USERNAME`、`SEED_ADMIN_EMAIL`、`SEED_ADMIN_PASSWORD` 环境变量。真实密码不放进 JSON。旧 `app.bootstrap-admin` 配置不再生效。

## 初始化与重复执行规则

- 18 个 `gl:system:*` 权限、6 个菜单、14 个按钮关联、1 个 `Administrator` 角色（稳定编码 `administrator`）。新建角色时关联 6 个菜单和 18 个权限。
- 首次创建管理员时设置超级管理员标记、BCrypt 密码和角色关联，并创建默认家庭、家庭成员和现金账户，不插入演示账目。
- 继续使用 `relations.sys_seed_history` 的 `system-base/1` 和 `admin-account/1`，搬迁模块不会清空历史，也不会重新执行已经完成的初始化。
- 首次执行匹配已有权限编码、菜单路径、按钮组合，保留已有名称、排序和隐藏状态；菜单路径重复时失败。
- 接管已有同名角色时保留授权，不自动扩权。已有同用户名、同邮箱且有效的超级管理员保留密码、资料及角色关系。
- 普通账号、已删除账号、用户名/邮箱身份不一致等冲突会导致整个 Seed 事务回滚，不自动提权或恢复账号。
- 同版本成功后直接跳过；人工改名、删按钮、撤权、改密码或取消超级管理员标记均不会被再次初始化恢复。管理员初始化完成后可清空初始密码。
- JSON 是初始默认值，不是每次启动覆盖数据库的配置。初始化完成后修改 JSON 不会自动更新已有库；后续需要补充新的初始化批次时，在 Java 中明确增加历史版本及增量操作，目录仍按服务组织。

角色授权和超级管理员标记独立；敏感接口仍要求超级管理员身份。

## 可选终端方式

使用 JDK 21 在项目根目录执行：

```powershell
mvn.cmd -s .mvn/settings.xml clean verify
./database-seed/seed.ps1 -JavaExecutable "$env:JAVA_HOME/bin/java.exe"
```

或：

```powershell
java -jar database-seed/target/database-seed-0.0.1-SNAPSHOT-exec.jar --spring.config.additional-location=file:./system-service/src/main/resources/application-local.yml
```

不再给 `system-service` 传 `--seed`。运行前核对配置连接的库；旧 `neondb` 的其他项目 4.x Flyway 历史不能直接用本项目迁移覆盖或清空。

## 登录与后续迁移

管理后台支持 `administrator` 用户名、邮箱或手机号登录。输入含 `@` 时作为邮箱、符合大陆手机号格式时作为手机号，其余作为用户名，区分大小写；保留原邮箱大小写兼容和手机号登录规则。请使用普通字母形式的管理员用户名，避免与邮箱/手机号登录标识混淆。

阿里云用户和账本导入是后续独立步骤。账号按身份匹配，并记录源 ID 到目标 ID 的映射；不能假设源用户 ID=1 就是目标管理员。导入用户资料和账目时，系统授权另行保留；家庭、历史家庭归属、记账人、账户和流水引用必须一起转换。当前仍未同步。
