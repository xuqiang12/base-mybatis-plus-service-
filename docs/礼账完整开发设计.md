# 礼账真实服务设计

日期：2026-10-23

## 目标

把当前 UniApp 礼账从“正式环境部分接口、其余本机 Mock”改为可跨设备使用的真实 Java 服务：邮箱登录后，家庭成员共享亲友、账簿、人情、借贷和月度家庭收支数据，刷新、重新登录和更换设备都从 PostgreSQL 恢复。

## 当前事实

- Java `system-service` 已有邮箱/密码登录、家庭成员邀请/加入/退出、亲友 CRUD 和 Flyway 基础迁移。
- Java `system-service` 已新增账簿、人情、借贷、家庭收支分类及月度收支表和接口，迁移版本为 `v3.4` 至 `v3.6`。
- 前端 `src/api` 仅声明 HTTP 请求；`src/business` 处理环境选择和业务字段转换，Store 管理共享状态。只有显式 Mock 模式才调用模拟响应。
- 前端环境已区分 `mock`、`local`、`domain`；真实模式请求失败或未登录不得回退 Mock。
- 前端金额契约使用整数分，后端数据库使用 `BIGINT amount_cents`。

## 方案

礼账业务继续放在单体 `system-service` 中，使用 `modules.ledger` 的 LedgerController、LedgerService、HouseholdService 及 dto/entity/mapper 组织实现。所有写操作先取得当前家庭并在事务内锁定家庭行，再校验对象归属；查询也必须带家庭条件。API 只透传参数和响应，通用 HTTP 层处理地址、Token、超时和通用错误，页面/Store 负责字段转换和业务提示。

业务数据表均保存 `family_id`、创建/更新时间；人情和借贷流水保存姓名、称谓、记录人及显示名称快照。删除亲友时先检查是否存在未结清借贷：本次已确认“禁止删除，先结清借贷”；无未结清借贷时解除人情/借贷关联并保留快照后删除档案。删除账簿只解除人情记录的 `book_id`，不删除流水。

家庭加入/退出已确认：加入不迁移双方旧数据；退出者获得新空家庭，原家庭数据留在原家庭，由仍在原家庭的成员继续访问。加入后原单人家庭的 hidden_owner 归原账号所有，通过“我的历史家庭”只读访问；不初始化历史分类、不写入当前家庭 Store。其他账号不能读取，现有写接口也不能修改历史家庭。不需要为此改写历史迁移。

月度家庭收支采用“一家庭一月份一张表，表内多分类合计”，以 `family_id + month` 唯一约束；再次打开同月执行查询/更新，不新增第二张月表。收入、支出、存款独立统计，结余为收入减支出，存款不计入支出。累计存款为各月存入额之和，不表示银行实际余额。首页趋势直接使用实际分类支出，禁止再用收入减存款反推支出。

## 错误和并发

- 金额必须为正整数分；借贷收款/归还在事务内锁定家庭和亲友相关流水后重算余额，余额不足返回业务错误。
- 所有跨家庭 ID 按“资源不存在或无权限”处理，不返回另一家庭数据。
- 真实模式未登录、接口失败、超时均保留错误状态，不显示保存成功，也不调用 Mock。
- 未接入模块在页面显示“暂不可用”，完成接入后移除提示。

## 验证范围

后端执行 Maven 单元/HTTP 集成测试、Flyway 迁移校验和真实 PostgreSQL smoke；前端执行现有 Node 测试、类型检查、H5/微信构建；联调覆盖登录、亲友、账簿、人情、借贷、月度收支、共享刷新和跨家庭拒绝。真机、真实邮件和双设备需在本机条件允许时单独记录，不能以构建成功替代。

## 整月接口与事务

- `GET /ledger/household/month?month=2026-10`：返回 `{id, month, items}`，尚未填写时 id 为 null、items 为空。
- `POST /ledger/household/month/save`：传 `{month, items:[{categoryId,type,amountCents,note}]}`。更新已提交分类，0 清除该项，未提交分类保留；前端一次提交本月全部可见分类。
- 整批在家庭锁和同一事务内执行。分类归属、方向、重复、停用限制任一失败均回滚。同家庭月份唯一，已有项按月份与分类更新。
- `GET /family/history/list`、`GET /ledger/history/data?familyId=...`：仅读取当前账号拥有的历史家庭；只读响应独立于当前家庭。
- JSON 禁止浮点转换为整数，金额使用 BIGINT 和整数分，浮点分返回 400。
- 分类和原月表项一次读取，月表时间一次更新；汇总一次读取月份，避免远程数据库反复查询造成 10 秒超时。
